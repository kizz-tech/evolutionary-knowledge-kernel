# EKK 0.8: continuous work

This release connects short context entry, discoverable intentions, versioned
continuation, optional practical methods, observations from actual use, read-only
author notes and durable local operations. Ordinary local edits can use zero EKK
calls and produce zero records.

The new `work`, `queue`, `task`, `source`, `guide` and `improve` commands share the
existing owner routing. `enter --brief` progressively discloses optional reading
while retaining governing restrictions. Search adds aliases, Unicode normalization,
partial lexical matching and exact fragments. Private disposable caches reuse
unchanged input without caching permissions or granting authority.

Work items and events use ordinary `ekk.record/0.1` records. Exact versions,
current permissions, source integrity, conditional writes and method admission
remain in force. The durable outbox acknowledges local storage separately from
publication and discoverability. Lost responses reuse the same logical key.
Author notes remain independent and read-only. Waiting needs an actual existing
host schedule receipt; external delivery remains unknown until reconciled.

See [continuous work](continuous-work.md) for the connected workflow. Technical
checks establish mechanism boundaries, not improved agent quality. Benefit is
assessed in ordinary owner use, selected task logs and feedback. No artificial
agent trial or mandatory number of tasks gates this workflow.
