# Интерфейсы и границы механизмов

Все следующие интерфейсы являются проектируемыми. Реальная команда в комплекте пока одна:
`python tools/validate.py <realm>`.

## Общий envelope запроса

`request_id`, `operation`, `workspace_id`, `target_realm`, `target_scope`,
`expected_snapshot` для изменения, `payload` и `idempotency_key` для повторяемой записи.

Acting principal и его grants поступают из доверенного окружения или серверного транспорта.
CLI пользователя может назвать профиль, но корпоративный сервер не доверяет входному
`principal: admin`. Для trusted-local режима явно указывается более слабая модель доверия.

Общий результат: operation status, использованный snapshot, данные, source references,
неполнота, предупреждения и подтверждённые/неподтверждённые гарантии. Ошибки различают
invalid_format, unresolved_binding, access_denied, stale_snapshot, unresolved_conflict,
unsupported_capability, source_unavailable и recovery_required. Сообщение об отказе
не раскрывает запрещённое содержимое или метаданные другого владельца.

## Proposals

Proposal содержит ожидаемый base snapshot, список изменений, основания и область воздействия.
Свободный текст может объяснить изменения, но writer принимает patch/files только внутри
разрешённых корней. Недоступный source отмечается явно. Последнее слово по правам не у LLM.

Draft proposal не является отдельной задачей, если намерение исполнить его не принято.
При изменении base writer отказывается от тихой перезаписи и возвращает конфликт.
Непересекающиеся changesets можно объединить с повторной проверкой нового снимка.

## Packs

Manifest pack содержит ID, version, requires_format, entrypoints, конфигурационную схему
и перечень явно заявленных исполняемых возможностей. Прочтение и установка не исполняют код.

Lock содержит version, origin и SHA-256 фактически установленного release artifact.
Digest вычисляется по распространяемому артефакту; если распространяется директория,
упаковщик задаёт детерминированный manifest путей и hashes, а не платформозависимый ZIP.
Значение hash не подставляется заранее и не трактуется как доказательство доверия автору.

Проект подключает pack ссылкой. Локальная настройка хранит только отклонения и область применения.
Upstream update создаёт кандидат обновления, не молчаливую замену принятых методов.
Изменение упаковки без изменения метода и изменение управляющего поведения различаются.

## Context bundles

Детерминированная часть: разрешение binding, authority, snapshot и объявленных обязательных
ограничений. Поисковая часть: ранжирование остального материала. Необязательная модельная
часть: summary с исходными ссылками. Summary не имеет большей силы, чем исходные записи.

Manifest фиксирует запрос, IDs contexts, версии записей, policy/pack digests,
разрешённую проекцию, время сборки, источники и степень полноты.
Сведения о закрытых источниках не публикуются через manifest.

## Подключённые системы

Adapter описывает доступные операции владельца: read, propose, execute, observe.
Наличие read connector не означает право записи. Недоступность внешнего владельца не
лечится созданием внутренней «официальной» копии календаря, задачи или runtime status.

Для multi-repo change хранится receipt с independent step outcomes. Повторный вызов
продолжает незавершённый шаг. UI не объявляет change полностью доставленным, пока
соответствующий внешний факт не наблюдён. Общая cross-realm atomicity не обещается.

## Переход к серверу

Сначала тот же application слой работает с server-authenticated principal и server-side writer.
Files/Git могут оставаться backend. При разных правах сотрудники получают только разрешённые
проекции, а не полный клон. Общие caches между grants по умолчанию запрещены.

Позднее canonical storage можно заменить только явным cutover с сохранением IDs, истории
принятий, source references, export/import и conformance. Индекс не становится canonical
просто потому, что в нём уже есть удобные таблицы.
