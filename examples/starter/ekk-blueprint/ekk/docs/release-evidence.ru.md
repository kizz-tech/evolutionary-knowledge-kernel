# Что должно сопровождать релиз

Релиз включает точные versions движка, формата и packs; changelog; поддерживаемые операции;
conformance-результаты; известные ограничения; migration path при изменении семантики;
и пример полноценного export/import независимого realm.

Сообщение «тесты прошли» должно обозначать, что именно проверялось. Отдельно указываются
реализованные controls, логические ограничения, платформенная изоляция, recovery tests
и оценка полезности на реальных задачах.

Пример хорошего публичного утверждения: «файловый parser обнаруживает нарушение X
в опубликованном fixture». Пример недоказанного утверждения: «система даёт enterprise security»
только потому, что schema содержит audience.

Научная статья ссылается на замороженный код и артефакты исследования. Пост в соцсетях может
показывать реальный before/after, но должен отличать личный case study от контролируемого сравнения.
Сам факт наличия постоянной памяти не доказывает рекурсивное улучшение эффективности.
