# What must accompany a release

A release includes exact engine, format, and pack versions; a changelog; supported
operations; conformance results; known limitations; a migration path when semantics
change; and an example of a complete export/import of an independent realm.

The statement "tests passed" must identify exactly what was checked. Implemented
controls, logical restrictions, platform isolation, recovery tests, and usefulness
evaluation on real tasks are reported separately.

An example of a sound public claim: "the file parser detects violation X in a
published fixture." An example of an unproven claim: "the system provides enterprise
security" merely because the schema contains audience.

A research paper references frozen code and research artifacts. A social media post
may show a real before/after, but must distinguish a personal case study from a
controlled comparison. Persistent memory alone does not prove recursive improvement
in effectiveness.
